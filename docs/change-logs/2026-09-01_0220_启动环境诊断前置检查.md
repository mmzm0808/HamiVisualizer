# 启动环境诊断前置检查

- 完成时间：2026-09-01 02:20:54 +08:00（北京时间）
- 范围：`hamivisualizer.main` 启动前环境检查；不改变模型格式、矩阵算法和 GUI 正常路径。

## 问题与目标

此前入口只在导入 NumPy 后检查主版本。当用户缺少依赖、PySide6 版本漂移，或处在 NumPy 2.x 与旧版 Qt 原生扩展不兼容的环境时，程序可能先进入原生模块加载，再给出难以判断的 traceback，甚至触发 Windows 访问冲突。对于实际用户，错误信息必须在打开 Qt 之前就能说明“缺什么、为什么不兼容、如何修复”。

## 实现

1. 新增 `_installed_version()`，通过 `importlib.metadata` 读取发行版版本，不导入 NumPy/PySide6/SymPy 的原生或重量模块；安装元数据缺失、损坏或读取失败统一按“不可用”处理。
2. `_check_runtime_compatibility()` 现在依次检查：
   - NumPy：必须为 1.x；2.x 给出 ABI 原因和 `python -m pip install "numpy>=1.26,<2"`；
   - PySide6：必须为 6.6.x；其它版本在 Qt 原生导入前阻止并给出精确安装范围；
   - SymPy：必须为 1.x，缺失或 2.x 直接给出 requirements 安装指引。
3. 正常环境返回版本字典，`main()` 后续仍按原顺序创建 QApplication、配置字体、加载 NP 初始模型；因此版本诊断只影响异常环境，不改正常启动体验。
4. 新增纯 Python 回归，覆盖当前已验证环境、缺失 PySide6、NumPy 2.x 和未验证 PySide6 四条路径，并断言错误信息包含可执行修复命令。

## 兼容性与风险

- 没有引入第三方包、网络请求或系统目录写入；检查只读取当前 Python 环境的安装元数据。
- 对未来 PySide6 主/次版本采用保守阻止策略，因为项目当前只验证 6.6.x；用户可按提示安装已验证范围，或在未来完成兼容性审计后放宽判断。
- 模型 JSON、保存位置、撤回历史、矩阵/能带/波函数计算和所有对外 Python 接口保持不变。
