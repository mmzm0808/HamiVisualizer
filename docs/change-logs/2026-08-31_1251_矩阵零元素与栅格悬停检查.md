# 矩阵零元素与栅格悬停检查

- 审计开始：2026-08-31 12:39:11 +08:00（上一批完整回归结束后）
- 实现与证据完成：2026-08-31 12:51:48 +08:00（北京时间）

- 影响范围：矩阵悬停定位、零元素检查、大矩阵栅格化路径、单击坐标共用、证据渲染工具和 README；不改变哈密顿量数值、元素分类配色、矩阵文字阈值或对外计算接口。

## 一、发现的缺口

上一批已把现有 tooltip 坐标改为一基，但继续沿完整检查链路审计后发现：

1. 智能/符号模式为了保持稀疏矩阵可读性，会把零元素的格内文字抑制为空字符串；旧逻辑只在文字非空时设置 tooltip，因此零元素没有悬停反馈。
2. 当矩阵阶数超过 `RASTER_THRESHOLD=64` 时，为了性能会改用一张 `QGraphicsPixmapItem` 栅格图；由于不再存在每格图形项，所有大矩阵元素都无法获得精确 tooltip。
3. 悬停坐标只显示 `H[row,col]`，没有告诉用户当前四边标尺所使用的 `cell:site` 逻辑标签。

## 二、实现方案

1. 新增统一场景坐标到矩阵单元格的映射入口，点击选中与悬停定位共用同一边界判定，避免两套 floor/范围逻辑漂移。
2. 小/中矩阵的每个底色格都安装 tooltip，文字为空时明确显示 `0`；数值模式的 `0.00` 精度表示保持不变。
3. 在 `QGraphicsScene.helpEvent` 中按鼠标场景坐标动态计算行列，因此大矩阵即使只有一张栅格图，也能按单元格显示实时数值。
4. 提示统一为 `H[逻辑行,逻辑列]（H[一基行,一基列]） = 值`；两种坐标相同时自动去除重复部分。
5. 证据工具新增 `--matrix-zero-selection-demo`，自动选取最靠近视图中央的精确零元素，避免截图因内容缩放而找不到高亮。

## 三、验证与边界情况

- 新增智能模式 2×2 零元素回归，确认空白格仍有 `H[1,2] = 0`、`H[2,1] = 0`；
- 新增 65×65 纯零栅格矩阵回归，确认场景坐标映射到内部 `(32,40)`，用户提示为 `H[33:A,41:A]（H[33,41]） = 0`；
- 通过伪造 `QGraphicsSceneHelpEvent` 走完真实场景帮助路径，确认事件被接收且提示文本正确；
- 首次测试还确认了数值模式会保留 `0.00` 而非抑制零文字，因此测试改为真正需要补齐的智能模式，没有错改现有精度语义；
- 矩阵专项回归：`17 passed, 184 deselected in 2.54s`；

## 五、兼容性和成功标准

- 零元素仍不在智能/符号矩阵中密集画文字，不牺牲稀疏结构可读性；
- 小矩阵、文字延迟显示矩阵和大栅格矩阵均可悬停检查任意元素；
- 点击与悬停使用同一单元格映射，边界上不应选到相邻错格；
- 内部零基索引、符号化简、元素值和绘图性能阈值保持不变，无破坏性变更。
