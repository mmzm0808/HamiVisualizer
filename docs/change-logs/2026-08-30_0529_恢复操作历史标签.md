# 恢复操作历史标签

- 时间：2026-08-30 05:29 +08:00
- 范围：`hamivisualizer/view/main_window.py`、`hamivisualizer/tests/test_ui_hardening.py`、`tools/render_ui_regression.py`
- 目标：让复合操作的历史标签表达真实用户动作，而不是依赖结构差异猜测。

## 发现

“恢复编辑前构型”会修改格点位置，旧实现通过前后文档差异将它标为“移动或编辑格点”。这会让撤销菜单、工具提示和底部状态栏失去语义，尤其在连续拖动后很难判断下一次撤销会做什么。

## 实施

1. `MainWindow` 增加一次性 `_pending_history_label`。恢复操作在提交快照前写入“恢复编辑前构型”，`document_committed()` 优先消费该标签；普通拖动、参数修改和跃迁编辑仍使用原有差异推断。
2. 标签消费放在提交路径中，应用快照失败时恢复原 pending 状态，不会污染下一次无关编辑。
3. 撤销/重做测试改为核对完整语义：恢复快照的 undo/redo 标签及状态栏都显示“恢复编辑前构型”，后续编辑仍可进入历史。
4. 离屏脚本将该链路输出为独立的 80%/100%/150%/180% 明暗主题证据。
