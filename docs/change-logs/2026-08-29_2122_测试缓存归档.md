# 测试缓存归档与工作区清理

时间：2026-08-29 21:22 +08:00

## 背景

项目已经把截图、诊断和测试运行产物集中到 `.codex-artifacts/`，但 pytest 默认仍会在项目根目录生成隐藏的 `.pytest_cache`。在 Windows 中文路径工作区中，该目录偶尔会被旧进程锁定，导致测试结束时出现权限警告，用户容易误以为是应用本身失败；同时也违背“项目产物集中管理”的约定。

## 修改

- 在 `pyproject.toml` 的 `[tool.pytest.ini_options]` 中设置 `cache_dir = ".codex-artifacts/test-runs/pytest-cache"`；
- 保留既有 `--basetemp=.codex-artifacts/test-runs/pytest-default`，使临时目录和缓存统一位于项目专属产物区；
- 只清理可确认不再被日志引用的旧截图，未删除任何代码、模型或用户配置。

## 验证

- 单元测试：编号回归 `1 passed`，无 pytest 缓存权限警告；
- 完整回归：`275 passed in 60.42s`，且不再出现根目录缓存权限警告；
- Markdown 引用检查：`739` 条本地链接，缺失 `0`；
- 截图清理后保留 `822` 张、约 `106.8 MiB`，全部位于 `.codex-artifacts/screenshots/`；
- 变更不影响模型 JSON、运行时计算、界面布局或对外启动命令。

## 结果

测试缓存与临时文件不再散落在项目根目录；后续测试结果可直接在 `.codex-artifacts/test-runs/` 中追踪。根目录残留的旧 `.pytest_cache` 受 Windows 文件锁保护，已停止继续写入，不影响新测试。
