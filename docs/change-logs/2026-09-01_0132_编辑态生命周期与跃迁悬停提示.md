# 编辑态生命周期与跃迁悬停提示

## 记录时间

- 影响范围：晶格编辑画布、跃迁系数交互、Qt 图元生命周期、离屏验收脚本

## 问题与复现线索

用户在 Windows 上编辑晶格、拖动格点或切换编辑状态时遇到 `python.exe - 应用程序错误`（访问了无效内存）的系统级弹窗；同时，旧版本模型在格点移动后可能在旧坐标留下一个圆。此前画布还缺少“悬停查看系数、点击后固定编辑”的明确反馈。

这类崩溃不是普通 Python 异常：晶格画布中的 `QGraphicsProxyWidget` 承载真实 `QLineEdit`，若在 Qt 鼠标/绘制事件尚未结束时同步销毁代理或其子控件，Windows 原生 backing store 仍可能持有悬空指针。编辑器尺寸变化也会频繁触发重排，多个无主 `singleShot` 回调叠加后会放大这个竞态。

## 实施内容

### 1. 编辑器和场景重建的安全生命周期

- `LatticeView` 新增场景自有的单次 `QTimer`，合并编辑器 resize、主题/界面缩放和提交后的重排请求；不再从这些路径投递无归属的全局单次回调。
- `set_data()` 重建时先停止重排/悬停清理计时器，隐藏并从 `QGraphicsProxyWidget` 脱离旧 `QLineEdit`，调用 `deleteLater()`；随后清空场景中的代理图元，最后仅对本轮脱离的控件发送 `DeferredDelete`。这样既满足旧控件及时消失的可观察契约，又避免控件仍挂在活动代理上时触发原生销毁。
- 悬停提示的延迟移除也改为场景自有计时器。窗口快速切换、主题重建或关闭时不会留下指向已销毁场景的回调。
- 主窗口界面缩放完成后的编辑器重排改为调用场景调度器，进一步消除窗口销毁后回调访问旧场景的机会。

### 2. 旧模型拖动的残留圆修复

- 编辑态下，数据快照中的普通圆不再盲目绘制；仅当快照坐标不对应当前可编辑格点或编辑基线时才保留，用当前编辑手柄作为移动格点的唯一视觉来源。
- 其他只读的 OBC/半无限上下文格点不会被误删；编辑会话基线仍会绘制为可吸附的参考环，因此“拖动后可回到原位”的交互保持不变。

### 3. 跃迁悬停与点击编辑

- 跃迁导引线支持真正的 hover：悬停时显示轻量的系数预览文字，不创建大量隐藏输入框，也不修改模型。
- 预览文字按物理跃迁中点定位，使用固定像素字体，带跃迁序号和“点击线条后可编辑”提示；离开线条后隐藏，点击格点会在当前 Qt 事件结束后安全移除。
- 点击导引线仍走原有 `activate_hop_editor()`，只创建/显示对应的右侧编辑框并保持其焦点；悬停不会抢焦点、不会启动画布平移，也不会改变跃迁表。
- 默认只对当前渐进式披露的主跃迁显示导引线；通过“显示次近邻/编辑细节”后，NNN 和长程关系同样可悬停检查，避免密集模型默认出现线条噪声。
