# 智能矩阵参数来源追踪

- 实施记录：2026-09-01 15:31:55 +08:00（北京时间）
- 最终验证：2026-09-01 15:46:14 +08:00（北京时间）
- 范围：智能矩阵标签、半无限 Bloch 谐波、OBC 建阵、参数数学排版、默认模型回归。

## 问题与物理风险

旧“智能识别标签”在数值 Hamiltonian 建好后，主要按矩阵元是否接近 `n*t` 来恢复文字。
这种办法只能覆盖 `t/phi/omg`，无法可靠区分 SSH 的 `t1/t2`、Haldane 的 `t2/m` 或用户
自定义参数。更严重的是，数值相同并不意味着来源相同：当 `t2=1`、`m=0.2` 时，数值
`-1` 同时可以写成 `-t2` 和 `-5m`；仅凭数值、对角/非对角位置或参数角色猜测，会向用户
展示错误的物理含义。

本轮先用完整参数表做倍数匹配并建立了失败测试，确认该方向存在不可消除的整数倍歧义；
随后按 Luna 执行 + Sol High 结构化推理的工作流复核方案。最终采用“数值真值 + 稀疏来源”
双轨，不发布任何靠数值猜测新参数名的实现。

## 实现

1. `HoppingTerm` 增加非持久化的 `label_expression`：保存未代入参数的幅度与相位表达式，
   只服务显示，不参与数值建阵、能带、波函数或模型文件。
2. 半无限 `build_ribbon` 与 OBC 建阵在复用同一套正反向规范化、反向副本去重、边界截断和
   Hermitian 共轭规则时，同步累积稀疏 provenance。键为 `(row, col, Bloch harmonic)`，
   不创建第二份 `Nat x Nat` SymPy 矩阵，存储量随实际非零跃迁增长。
3. `HResult.smart_label_expressions()` 按每个 Bloch 谐波将来源表达式代入当前参数，逐项与
   `H0/H1/extra/H` 的数值系数回算。缺来源、非有限、谐波缺失或数值不一致时，整格删除
   符号标签并退回原数值格式，禁止“部分正确、部分遗漏”的混合显示。
4. Matrix DTO 新增稀疏 `smart_labels`，小矩阵图元、栅格大矩阵覆盖层、点击详情、tooltip
   和 LaTeX 复制均复用同一来源；`kx` 滑动复用缓存，不重复简化来源表达式。
5. 数字后缀参数统一按数学下标排版：`t1 -> t_{1}`、`t12 -> t_{12}`、`lambda2 -> lambda_{2}`；
   `e^{+-ik_x}` 继续由现有数学布局渲染，`x` 保持为 `k` 的下标。

## 兼容性与影响

- 数值 Hamiltonian、Bloch 约定、边界条件、模型 JSON、参数归一化和公开构建接口未改变；
- 旧代码未提供 `label_expression` 时 provenance 会标记为不完整，界面安全退回旧数值标签；
- 旧 `ElementFormatter(t, phi, omg)` API 与原有启发式规则保持兼容；
- provenance 使用稀疏字典，不随矩阵零元素按平方增长，也不在 `kx` 拖动时重建。

## 验证

- 跃迁比例专项：蜂窝 `1.2/0.3/0.3 -> -4*t/-t/-t` 与 `t=0.3` 保持通过；
- 精确来源专项：SSH 在 `t1=t2=1` 时仍同时保留 `t1/t2`；Haldane 同时保留
  `t/t2/m/phi`；故意制造 provenance/数值不一致时标签为空并退回数值；
- 全默认审计：NP、SC、空白自定义、方格、一维链、蜂窝、三角、Kagome、SSH、Haldane
  在半无限与双开边界下逐一重建，来源符号均属于各自已声明参数；
- 定向物理与 UI 回归：`64 passed`、默认模板/Bloch/斜元胞/符号专项 `52 passed`、
  全默认来源专项 `13 passed`；Python 编译和 `git diff --check` 通过；
- 首次完整回归为 `456 passed, 1 failed in 280.14s`，唯一失败是新增两张证据后简报仍写
  `745`；计数改为 `747` 后，最终完整回归为 `457 passed in 439.77s`；
- Python 编译、`git diff --check`、简报时间倒序和证据总数契约均通过。
