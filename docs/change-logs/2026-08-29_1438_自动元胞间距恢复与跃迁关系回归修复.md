# 自动元胞间距恢复与跃迁关系回归修复

- 时间：2026-08-29 14:38（+08:00）
- 范围：`hamivisualizer/view/main_window.py`、`hamivisualizer/view/control_panel.py`、相关 UI 回归与离屏工具。
- 背景：上一轮为跃迁表增加胞内/胞间行高亮和右键快捷编辑后，继续按“编辑—调整间距—恢复”的真实流程复核，发现一个恢复边界错误，并在回归中捕获一处 PySide6 调色板 API 使用错误。

## 问题定位

### 1. 自动元胞尺寸无法完整恢复

编辑会话基线可能是 `cell=None`，含义是让程序根据格点自动推断元胞间距。旧的 `_restore_edit_baseline()` 只有在基线 `cell` 非空时才写回 `cell` 字段；如果用户先手动输入 `Lx/Ly`，再点击“恢复原始构型”，格点会恢复，但手动间距仍然残留。该行为与“恢复编辑前几何”的按钮语义不一致。

### 2. 跃迁行高亮的枚举调用不兼容 PySide6

新增行高亮最初把 `QPalette.Base/AlternateBase/Highlight` 直接传给 `palette.color()`。在部分 PySide6 版本中，这些旧式别名不能稳定匹配 `color()` 重载；编辑表格单元格时会从 Qt 信号回调抛 `SystemError`，随后可能递归触发关系更新。离屏初始截图不一定暴露此问题，因此必须用真实 `cellChanged` 路径回归。

## 实施修改

1. `_restore_edit_baseline()` 现在始终写回基线 `cell`：
   - `None` 明确恢复为自动间距；
   - 矩形 `Lx/Ly` 和斜原胞 `a1/a2` 继续深拷贝恢复；
   - 其他参数、跃迁、边界和显示选项保持当前值，不扩大“恢复原始构型”的作用范围。
2. 行高亮改用 `QPalette.ColorRole.Base/AlternateBase/Highlight`，兼容 PySide6 的枚举重载；关系色仍由当前主题调色板混合生成，未锁死 RGB。
3. 新增回归 `test_restore_edit_baseline_removes_new_spacing_override_when_original_was_auto`，真实构造 `cell=None → Lx/Ly 手动覆盖 → 恢复` 流程；并补跑跃迁关系行/菜单相关回归。
4. 离屏工具新增 `--restore-spacing-demo`；恢复态在 100%/150% 浅色/深色下抓取。上一轮 `--hop-relation-demo` 的 16 张主画面/右键菜单截图也在调色板修复后全部重新生成。
