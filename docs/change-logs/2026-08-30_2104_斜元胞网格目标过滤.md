# 斜元胞网格目标过滤

- 时间：2026-08-30 21:04:18 +08:00
- 类型：编辑器交互一致性、网格目标校验
- 影响范围：`hamivisualizer/view/lattice_view.py` 的网格装饰绘制及对应 UI 回归；不改变吸附算法、模型坐标、跃迁关系或哈密顿量计算。

## 背景与问题

上一轮把网格从整个场景收敛到“当前可编辑元胞附近”，解决了右侧系数引线区被网格淹没的问题。但斜元胞使用轴对齐包围框时，包围框角落仍可能出现落在真实 Bravais 平行四边形之外的网格点。用户看到这些点会自然地认为它们可以吸附；实际上格点工具会按分数坐标校验并拒绝元胞外位置，形成“看得见但点不了”的交互矛盾。

## 实施内容

### 1. 绘制前做真实元胞判定

`_draw_snap_grid()` 在受约束模型中，使用当前 `a₁/a₂` 和编辑锚点把候选网格点转换为分数坐标：

\[
u = \frac{x a_{2y} - y a_{2x}}{\det(a_1,a_2)},\qquad
v = \frac{a_{1x} y - a_{1y} x}{\det(a_1,a_2)}.
\]

只有 `0 ≤ u < 1` 且 `0 ≤ v < 1` 的点才创建可见网格节点；候选点仍以轴对齐工作区计算，随后过滤包围框外的区域。这样既保留稳定的绘制范围，又保证每一个可见点都对应合法的原始元胞位置。

### 2. 计算路径与交互路径保持一致

- “网格点”开关和“间距”输入仍即时生效；
- 吸附关闭时仍保留自由坐标输入；
- 添加格点的元胞边界、重复点和有限数值校验不变；
- `snap_position()` 没有改写，现有拖动/恢复行为和物理矩阵结果不受影响；
- 无 `cell_vectors` 的独立插件场景仍使用原有完整场景回退。

### 3. 避免重复计算

将行列式和基矢读取移到网格循环外，点级循环只完成坐标转换与范围判定，避免细网格下不必要的重复计算。

## 风险与后续观察

对于极粗的自定义间距，合法元胞内可能只剩少量网格点，这是物理范围与用户设置共同决定的结果，而不是把非法点显示出来。后续如需要更密的视觉参考，应调小“间距”，不应放宽元胞边界过滤。
