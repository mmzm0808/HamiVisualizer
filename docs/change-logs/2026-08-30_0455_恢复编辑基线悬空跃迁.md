# 恢复编辑基线时的悬空跃迁修复

时间：2026-08-30 04:55 +08:00

## 问题背景

编辑模式的“恢复原始构型”原本只恢复格点位置和元胞矢量，同时保留用户对参数和跃迁的编辑。这一语义本身是合理的，但存在一个边界情况：用户先添加格点并创建指向该新格点的跃迁，再恢复原始格点集合时，跃迁表会留下超出当前格点数量的端点。控制器重新校验文档时会拒绝整个模型，导致恢复动作失败，用户既拿不回原始几何，也看不到清楚的原因。

## 实施修改

### 主窗口恢复逻辑

文件：[main_window.py](../../hamivisualizer/view/main_window.py)

- 恢复格点和元胞定义前，遍历当前跃迁列表；
- 只保留 `from_site` 与 `to_site` 都落在恢复后格点范围内的跃迁；
- 非字典行、端点无法转成整数、端点超出恢复后格点数量的行会被安全丢弃；
- 合法跃迁的胞间偏移、幅度、相位和其它字段完全保留；
- 若发生丢弃，底部状态栏明确提示“已恢复编辑前构型；已移除 N 条指向新增格点的无效跃迁”；没有丢弃时保持原有成功提示；
- 仍然保留参数和其它有效跃迁编辑，不改变“几何恢复、物理参数不回滚”的既有契约。

### 回归测试

文件：[test_ui_hardening.py](../../hamivisualizer/tests/test_ui_hardening.py)

新增 `test_restore_edit_baseline_drops_only_hops_to_new_sites`：

1. 建立单格点半无限模型并进入编辑模式；
2. 模拟增加第二格点；
3. 同时加入一条合法原格点胞间跃迁和一条指向新增格点的跃迁；
4. 执行恢复；
5. 验证原始格点恢复、合法跃迁保留、悬空跃迁只被移除、状态栏给出解释。

### 离屏验收工具

文件：[render_ui_regression.py](../../tools/render_ui_regression.py)

新增 `--restore-topology-demo` 场景。它真实走“增加格点/悬空跃迁 → 恢复原始构型”的路径，避免只通过单元测试而没有检查最终界面反馈。该工具仍只把截图写入项目内的 `.codex-artifacts/screenshots/`，不会写入系统临时目录或用户模型目录。

## 后续建议

下一步可继续把“恢复原始构型”与撤销栈的关系做成更清晰的操作提示：恢复用于几何基线，`Ctrl+Z` 用于完整历史回退，并在状态栏/菜单提示中明确区分两者，避免用户把两种恢复语义混为一谈。
