# pytest 临时目录项目内收口

## 问题

项目约定所有测试临时数据写入 `.codex-artifacts/test-runs/`，但 pytest 默认的 `tmp_path` 仍使用系统用户 Temp。开发者直接运行 `pytest` 时，测试产物会离开项目目录；在当前 Windows 环境还会触发系统 Temp 权限锁。

## 修改

- 在 `pyproject.toml` 的 pytest 默认参数中加入
  `--basetemp=.codex-artifacts/test-runs/pytest-default`；
- 显式命令行传入的 `--basetemp` 仍可覆盖默认值，用于隔离不同验收批次；
- `.gitignore` 已忽略该项目内生成目录，不会把测试产物带入发布包。

## 验证标准

- 直接运行 `python -m pytest` 时，`tmp_path` 位于项目 `.codex-artifacts/test-runs/`；
- 测试失败或中断不会在系统 Temp 新增项目测试目录；
- 现有测试行为与模型/界面功能不变。

## 实际验证

- 直接运行 `python -m pytest -q`：`132 passed in 21.80s`；
- 实际 pytest 基准目录为项目内 `.codex-artifacts/test-runs/pytest-default/`；
- 测试后的 Python 缓存已清理；
- 既有三档界面截图继续作为 UI 非回归证据，未产生额外系统临时文件。
