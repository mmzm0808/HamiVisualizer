# 谱计算线程关闭生命周期防护

- **记录时间**：2026-09-01 03:27:17 +08:00（Asia/Shanghai）
- **范围**：后台能带/波函数计算、主窗口关闭时序、Qt 信号载体生命周期
- **性质**：稳定性修复，不改变模型格式、矩阵数值、能带或波函数的物理语义

## 问题与根因

用户提供的 Windows `python.exe - 应用程序错误` 属于原生层访问冲突。前一轮已收紧
晶格编辑器代理控件和主窗口延迟回调；继续审计发现后台谱计算仍存在另一条独立风险：

1. 能带/波函数使用 `QThreadPool` 执行 NumPy/LAPACK 任务；
2. `_SpectralSignals` 原先挂在 `ViewController` 下；
3. 关闭窗口会销毁控制器及其子对象，但后台 QRunnable 可能仍在返回并发射信号；
4. 这会让工作线程触碰已经销毁的 Qt 信号载体或排队中的 GUI 回调，尤其容易在大尺寸
   模型、快速关闭或连续切换时触发原生崩溃。

## 实施方案

- 信号载体改为无父对象，由正在运行的 worker 持有到任务结束，不再随窗口同步销毁；
- worker 增加独立 `done` 生命周期信号和返回状态，确保数值线程结束后才释放载体；
- `ViewController.shutdown()` 在窗口真正接受关闭前执行：停止防抖计时器、使当前代次失效、
  清空谱上下文、断开 GUI 成功/失败回调，并把仍在运行的 worker 放入短暂的模块级隔离区；
- 隔离区只保留到 worker 的 `done` 信号，随后立即释放，不阻塞用户关闭窗口，也不强制中断
  不可安全取消的 LAPACK 运算；
- 主窗口的三条正常关闭路径（工作区、无脏数据、保存后关闭）统一调用控制器关闭收口；
  用户点击“取消”而不关闭时不会触发该收口；
- 关闭期间到达的谱结果会被丢弃，绝不会刷新已经失效的矩阵、能带或波函数控件。

## 影响与兼容性

- 正常计算路径仍在后台执行，界面不会因为关闭而等待大矩阵分解；
- 只影响窗口销毁和过期结果处理，不改变对外控制器接口；新增的 `shutdown()` 是幂等的，
  可由关闭路径安全重复调用；
- 没有把 `HamiltonVisualizer.m` 或任何用户模型上传/纳入版本控制。
