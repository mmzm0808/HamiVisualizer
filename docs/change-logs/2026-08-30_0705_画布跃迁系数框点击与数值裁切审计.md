# 画布跃迁系数框点击与数值裁切审计

时间：2026-08-30 07:05 +08:00

## 背景

右侧跃迁系数框采用 `QGraphicsProxyWidget` 嵌入晶格场景，并固定为屏幕像素大小。此前回归测试只点击了代理项的场景锚点，没有覆盖用户真正会点击的输入框中心；同时，输入 `1/3` 后，字段由单字符 `1` 变成较长的小数，固定宽度和编辑器的水平滚动位置会让开头字符被裁掉，看起来像“输入没有成功”。

## 发现与修复

1. **真实点击路径补齐**
   - 新增中心点击回归：点击字段可获得焦点，画布不会启动平移，按 Enter 提交后参数表与模型文档同步更新。
   - 画布字段与左侧参数编辑器继续共用安全分数解析规则，`1/3` 被解析为 `1/3` 的浮点值，非法输入仍只在字段上提示，不破坏当前场景。
2. **字段宽度改为按字体测量**
   - 新增 `_strength_editor_width()`，依据实际字体宽度加边框/内边距余量计算固定像素宽度，范围保持在 `68…260 px`；上限覆盖 180% 界面缩放下的字体度量，同时仍避免密集晶格的右侧栏被无限拉宽。
   - 初始值和提交后的值都使用同一套宽度计算，支持普通小数、科学计数法和分数转换后的长小数。
3. **提交后的显示状态修正**
   - 交互字段显示统一保留 8 位有效数字；信号仍传递完整解析浮点值，因此只是显示精简，不改变哈密顿量数值。
   - 提交后把光标放回开头，避免 QLineEdit 自动把水平视口滚到末尾而隐藏 `0.`；字段尺寸改变后触发右侧栏重排，完整边框和点击区域保持可见。

## 验证

- 定向 Qt 回归：跃迁系数相关 `49 passed`；新增中心点击、分数提交、参数同步、无画布平移、缩放重测和文本宽度断言。
- 离屏真实交互场景：Kagome 半无限模型、最近邻、晶格编辑态、全部系数框，分别在 100%/180% 界面缩放和浅色/深色主题下生成截图；完整目录：[画布系数框审计](../../.codex-artifacts/screenshots/hop-editor-audit-20260830/)。
- 代表图：[180% 深色](../../.codex-artifacts/screenshots/hop-editor-audit-20260830/hop-editor-dark-180.png)、[100% 浅色](../../.codex-artifacts/screenshots/hop-editor-audit-20260830/hop-editor-light-100.png)。截图中第一项已通过真实点击输入 `1/3`，字段开头和完整圆角边框均可见，右侧栏未与格点重叠。

## 兼容性与影响范围

- 未改变模型 JSON 结构、跃迁行编号、胞内/胞间语义或 Hamiltonian 计算；只改善画布输入控件的尺寸、焦点和显示精度。
- 右侧栏仍保持单列布局和 progressive disclosure 引线策略，不会因为字段变宽重新引入密集引线网。
