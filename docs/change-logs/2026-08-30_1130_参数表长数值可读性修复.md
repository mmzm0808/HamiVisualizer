# 参数表长数值可读性修复

- 日期：2026-08-30（原记录未附具体时刻）
- 范围：左侧“参数”表的编辑、滑块联动和 100% 界面缩放
- 性质：交互与排版修复，不改变哈密顿量、矩阵元或文件格式

## 问题

用户输入分数或高精度小数后，`QTableWidget` 仍沿用旧列宽。高缩放下，参数名可能显示为 `O...`，数值可能显示为 `0....`；即使表格右侧还有空间，完整数值也无法确认。仅在初始化时重排列宽，无法覆盖逐字输入、滑块更新和缩放后的 Qt 布局重排。

## 修改

1. `ControlPanel._fit_param_table_columns()` 现在根据当前字体实际测量参数名、数值和表头，并为 QSS 的左右内边距预留额外空间；优先保留完整数值，再压缩参数名，最后才压缩滑块列。
2. 参数单元格每次编辑（包括输入 `1/13` 过程中暂时无效的中间文本）都会触发列宽重排；滑块改值也会同步重排，避免两条编辑路径表现不一致。
3. `MainWindow._set_ui_scale()` 在布局完成后追加一次延迟重排，覆盖 100%↔180% 切换时 QTableWidget 对列几何的再次调整。
4. 参数表关闭自动省略号绘制，完整值由列宽预算负责显示；若用户自定义名称极长，仍会优先保留数值和可用滑块空间。

## 验证

- 回归测试：长数值编辑后，数值列宽 ≥ 文本宽度 + 边距，且横向滚动条最大值为 0；UI 缩放原有断言改为允许无障碍边距增加的列宽。
- 定向测试：`2 passed, 24 deselected`。
