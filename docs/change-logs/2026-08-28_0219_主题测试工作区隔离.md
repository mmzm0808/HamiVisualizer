# 主题测试工作区隔离

- 修改时间：2026-08-28 02:19:06 +08:00
- 类型：测试基础设施缺陷修复
- 影响文件：`hamivisualizer/tests/test_theme.py`

## 问题

主题测试的 `_window()` 直接调用 `enable_workspace_mode()`，但没有替换
`MainWindow._workspace_root`。测试因此读取真实用户 `~/.hvisual/workspace.json`，
恢复真实模型标签，并可能触发真实路径自动保存。若保存失败，`QMessageBox` 会在
offscreen 测试中永久等待，表现为测试套件在首个主题用例处卡死。

这同时违反了测试不得接触用户数据的隔离原则，使“102 项通过”依赖本机状态。

## 修改

- `_window(workspace_root)` 现在强制接收测试临时目录；
- 在启用工作区模式之前写入 `win._workspace_root = workspace_root`；
- 所有创建主题窗口的测试都使用 pytest 的 `tmp_path`；
- 偏好持久化测试不再在窗口创建后临时换根目录，保证整个生命周期一致。
- 新增 `hamivisualizer/tests/conftest.py` 自动清理夹具：每个测试结束后隐藏
  Qt 顶层窗口、安排 `deleteLater()`，并处理 DeferredDelete 事件。这样应用级
  主题切换不会反复重绘前面几十个测试遗留的窗口。

## 成功标准

1. 主题测试不读取或写入 `C:/Users/.../.hvisual`；
2. 主题测试可独立、重复运行并正常退出；
3. 全量测试不再在主题模块入口卡住。
