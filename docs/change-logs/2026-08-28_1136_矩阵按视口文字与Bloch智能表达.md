# 矩阵按视口文字与 Bloch 智能表达

- 修改时间：2026-08-28 11:20:00 至 11:36:00 +08:00
- 类型：矩阵交互、半无限物理表达、大矩阵性能、冻结标尺、视觉回归
- 影响范围：`HResult.to_semi`、智能符号格式、矩阵场景、矩阵点击、
  视觉回归工具、控制器矩阵快路径

## 审计发现

1. 9–64 阶矩阵可以在放大后懒加载文字，但文字继续随场景同比放大，
   高倍率时会成为相互覆盖的巨字。
2. 65 阶以上矩阵使用单张栅格热图，原逻辑永远不生成文字，用户即使
   放大到单元很大也只能看到色块。
3. 半无限非“完整符号模式”的默认智能矩阵先代入当前 `kx`，因此单元格
   丢失 Bloch 相位的结构信息，只在状态栏标题看到 `kx` 数值。
4. 直接把数值矩阵提升为 SymPy 会把 `1/sqrt(2)` 一类系数显示成长浮点、
   根式和虚部碎片，不适合交互界面。
5. 四边冻结标尺在视口角落可能与矩阵文字互相覆盖。
6. 单元文字已经清晰可读时仍点击弹出模态详情框，打断连续浏览。

## 修改

### 1. 半无限智能矩阵始终保留 `kx`

- `HResult.to_semi(kx_symbol)` 可将数值 `H0/H1/Hn` 安全提升为符号矩阵；
- 默认智能模式分别保存：
  - `values`：当前 `kx` 代入后的数值矩阵，供判色、详情数值和计算；
  - `matrix`：只保留 `kx` 的结构矩阵，供单元文字显示；
- 纯数值模式仍忠实显示当前 `kx` 代入后的复数；
- 完整符号模式仍保留全部 `t/phi/omega/kx` 符号。

### 2. Bloch 智能格式器

新增按谐波分组的 `format_bloch_elem`：

1. 将表达式按 `exp(i*n*kx)` 的整数谐波聚合；
2. 先把每个复系数交给既有 `ElementFormatter` 识别为 `t`、`phi`、`omega`；
3. 再附加紧凑的 `e^{±ik_x}` 或 `e^{nik_x}`；
4. 同一谐波的实部/虚部先合并，避免出现两个浮点碎片；
5. 多项式用清晰的加减号连接。

因此默认 NP 模型显示为 `-t·e^{iφ}`、
`-t·e^{iφ} - t·e^{iφ}·e^{-ik_x}` 等，而不是
`-0.707106... + sqrt(2)/2 i ...`。

### 3. 中等矩阵的恒定可读文字

- 单元屏幕边长达到 34 px 才创建/显示文字；
- 文字使用 `ItemIgnoresTransformations` 保持恒定像素字号；
- 图元锚点固定在单元中心，继续放大只扩大单元，不扩大字体；
- 矩阵缩小时自动隐藏，避免密集重叠。

### 4. 大矩阵按视口渲染

- 65 阶以上仍保持单个栅格热图，不创建 O(n²) 个文字图元；
- 达到阅读阈值后，在 `draw_viewport_overlay` 中只遍历当前可见行列；
- 平移时按需格式化当前可见单元；
- 长文字按实际单元像素宽度省略；
- 文字绘制限制在四边标尺围成的中央区域，半露出的边缘单元不画截断文字。

### 5. 视口相关点击策略

- 点击时从事件所属 viewport 找到具体 `QGraphicsView`；
- 以该视口的“单元场景尺寸 × 当前缩放”判断文字是否可读；
- 已显示文字：不发出 `cellClicked`，不弹框；
- 未显示文字：保留详情弹窗，作为小缩放下的辅助读取方式；
- 同一 scene 被组合页和独立矩阵页共享时，各自按真实缩放独立判断。

### 6. 四边冻结标尺

- 行列号继续固定在窗口四边，而不是矩阵绘图范围边缘；
- 列号避开左右行标尺，行号避开上下列标尺；
- 大矩阵文字不覆盖四边标尺；
- 放大并平移到矩阵中部仍显示当前可见逻辑坐标。
