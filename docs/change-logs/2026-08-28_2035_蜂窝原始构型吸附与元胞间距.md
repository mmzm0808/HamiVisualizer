# 蜂窝原始构型吸附与元胞间距

- 日期时间：2026-08-28 20:35 +08:00
- 范围：蜂窝/石墨烯斜原胞编辑、编辑会话恢复、磁性吸附与控制器生命周期
- 状态：已实现、截图与专项回归通过

## 问题与诊断

蜂窝晶格的格点坐标含有 `sqrt(3)/2`。原有吸附会在一次拖动过程中优先贴回当前格点，但控制器完成防抖重算后，当前格点就变成了已移动的坐标；原始构型不再是下一次吸附候选。于是用户只能猜数值、拖回近似位置，或使用整组恢复按钮。

同时，编辑会话的基准构型由 `MainWindow.controller` 获取。正式启动入口会手工设置这个关系，但嵌入式预览、测试或新的启动路径可能遗漏它，从而使恢复和原始构型吸附静默失效。

## 改动

### 编辑会话的“原始构型”磁性吸附

- `LatticeView` 新增独立的只读吸附参考格点；
- 进入编辑模式时，窗口从当前模型完整捕获原始 sites，并同时交给晶格场景；
- 每次模型因拖动而重算后，当前格点会更新，但原始参考格点保留到退出编辑模式；
- 在原始位置附近松开时会自动贴回，仍保留现有的网格吸附、精确石墨烯位置候选与 Alt 自由移动；
- 退出编辑模式立即清空参考，保证没有跨模型/跨会话的陈旧吸附目标。

### 明确恢复与元胞间距

- 工具栏“恢复位置”改名为 **恢复原始构型**，提示明确说明它会同时恢复格点位置与 `a₁/a₂`；
- 左侧 `a₁ 长度`、`a₂ 长度` 保持为相邻元胞平移距离：改长度时斜原胞方向不变，仅缩放对应平移矢量；精确分量仍可在下方输入并通过“应用元胞矢量”提交；
- 恢复后重新登记同一份原始吸附参考，后续继续编辑也可随时贴回；
- `ViewController` 现在自行注册到所属窗口，避免不同启动路径漏掉编辑基准捕获。
