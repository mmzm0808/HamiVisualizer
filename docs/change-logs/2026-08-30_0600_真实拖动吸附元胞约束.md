# 真实拖动、吸附与元胞边界约束

## 背景

此前的普通点击回归已经确认“单击只选择，不会让格点或跃迁凭空消失”。本轮继续走更接近真实用户的按下—移动—释放路径，重点检查快速拖动、智能吸附、斜元胞和恢复操作。审计覆盖 NP、SC、空白自定义、方格、一维链、蜂窝、三角、Kagome、SSH、Haldane 十个内置预设，均使用半无限 x-Bloch、`NX=4`、`NY=3`、最近邻骨架。

## 发现的问题

真实拖动一个位于元胞边缘的格点时，指针可以把它甩到声明的原胞外。控制器随后仍会把坐标写入表格，直到下一次序列化/保存才暴露错误，表现为模型无法读取或计算。这不是用户应该承担的错误恢复路径。

## 实施修改

- `LatticeView` 记录控制器提供的 Bravais 向量；当编辑上下文明确给出元胞向量时，启用交互式元胞约束。
- 新增 `constrain_edit_position()`：将场景坐标转换到元胞分数坐标 `(u,v)`，把拖动结果限制在 `[0,1)` 的有效平行四边形内，斜元胞与矩形元胞统一处理。
- `_EditableSiteItem.itemChange()` 在磁吸之后再次执行约束；因此快速移动、网格吸附和磁吸恢复都不会产生非法中间坐标。
- 释放事件在 Alt 自由移动路径上也执行同一约束。Alt 只关闭磁吸，不会绕过模型有效性规则。
- 上边界采用 `1-1e-7` 的安全余量，避免坐标表的八位有效数字显示时四舍五入回 `1.0`，从而再次触发严格的 `u/v < 1` 校验。
- 无 `cell_vectors` 的独立 `LatticeView` 仍保持自由坐标，兼容插件和轻量集成调用。
- 回归脚本新增 `--drag-snap-demo`，使用真实 viewport 按下、带左键移动、释放事件，并在每个 UI 缩放档重新显示“坐标保持在元胞内”的状态反馈。

## 验证结果

- 新增回归：`test_real_press_move_release_drag_updates_site_and_keeps_hops`，覆盖全部十个默认预设；每个预设均验证坐标确实更新、跃迁条数保持、文档可序列化，并能恢复到编辑基线。
- 新增斜元胞/独立场景单测：`test_edit_position_constraint_handles_oblique_cells_without_affecting_standalone_scene`，确认斜平行四边形按分数坐标约束，未传元胞向量的轻量场景不受影响。
- 定向回归：`2 passed`。
- 全量回归：`292 passed in 71.55s`，无失败。
- `compileall` 继续通过。
- 离屏实拍：十个预设 × 80%/100%/150%/180% × 浅色/深色，共 80 张，目录为 [`drag-snap-audit-20260830`](../../.codex-artifacts/screenshots/drag-snap-audit-20260830/)。代表图：[`Kagome 180% 深色`](../../.codex-artifacts/screenshots/drag-snap-audit-20260830/drag-snap-Kagome-180-dark-180.png)、[`三角 150% 浅色`](../../.codex-artifacts/screenshots/drag-snap-audit-20260830/drag-snap-三角-150-light-150.png)、[`蜂窝 100% 深色`](../../.codex-artifacts/screenshots/drag-snap-audit-20260830/drag-snap-蜂窝-100-dark-100.png)。截图均显示完整编辑工具栏、元胞框、格点和底部拖动反馈。

## 影响与兼容性

这是交互层的安全约束，不改变哈密顿量、跃迁编号或模型文件格式。用户仍可在元胞内自由移动；跨元胞耦合继续由跃迁表的 `dx/dy` 表达。对于需要在元胞外绘制临时点位的外部 `LatticeView` 调用，只要不传 `cell_vectors`，原有自由坐标行为不变。
