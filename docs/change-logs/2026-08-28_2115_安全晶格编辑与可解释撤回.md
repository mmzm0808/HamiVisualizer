# 安全晶格编辑与可解释撤回

- 完成时间：2026-08-28 21:15 +08:00
- 状态：完成
- 影响范围：晶格编辑、模型新建提示、每个模型标签页的撤回/重做、离屏界面验收工具。

## 问题与原因

普通点击格点过去会隐式占用“两点建键”的第一步。它把选择、拖动和建键混在同一手势中：用户只想选中或检查一个格点时，第二次点击就可能创建跃迁并触发重建，视觉上像格点或连线“莫名消失”。同时，撤回虽然已有快照数据，但菜单不说明下一步会撤销哪一项编辑，难以放心使用。

## 实施改动

1. 晶格编辑改为显式工具流：正常单击只选择，拖动只移动；只有启用工具栏“添加跃迁”后，两个格点的点击才会创建跃迁。完成一条连线后工具自动退出，Esc 或再次点击按钮取消。
2. 新建模型预览同步这套规则，明确告知“先点击工具栏‘添加跃迁’，再选择两个格点”，不再保留旧的误导性文案。
3. `DocumentHistory` 为每个快照保存用户可读标签；撤销/重做菜单与工具提示显示下一项操作，例如“撤销：移动或编辑格点”。标签跟随撤销、重做和历史上限裁剪，不影响已保存模型格式。
4. 离屏截图工具的历史演示使用项目截图目录内的临时工作区，并关闭自动保存；验证结束后自动清除临时工作区。它不再读取或写入真实 `~/.hvisual`，也不会因未保存确认框卡住。

## 验证与成功标准

- Qt 界面与工作区回归：`81 passed in 23.29s`。
- 新增断言覆盖：正常点选不会开启建键、显式建键触发后重建不丢失格点、创建模型提示与真实手势一致、撤回按钮准确显示下一项标签、标签在撤回/重做中随快照移动。
- 截图验收：深色主题、150% 界面缩放下，晶格、尺寸控件、编辑入口均完整显示：[最终截图](../../.codex-artifacts/screenshots/undo-label-audit-20260828/history-label-dark-150.png)。
- 唯一警告为历史 `.pytest_cache` 的既有权限限制；测试本身全绿，未新增运行时失败。

## 兼容性与风险

- 不改变哈密顿量、跃迁表达式或 `.hvisual` 的对外格式。
- 这是有意的交互行为调整：依赖“先后两次普通单击建键”的旧习惯不再生效，改为明确的“添加跃迁”工具，以避免无意编辑。
