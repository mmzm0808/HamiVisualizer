# 高缩放系数框首字符裁切修复

- 日期：2026-08-30 11:45 +08:00
- 问题范围：晶格编辑态右侧跃迁系数输入框
- 影响范围：提交分数后重建、切换主题或切换到 180% 界面缩放的编辑器显示

## 问题证据

在蜂窝模型中把画布系数输入为 `1/3` 后，数值已经正确归一化为 `0.33333333`，但 Qt
重建 `QLineEdit` 时光标默认停在文本末尾。中心对齐的行编辑器会保留末尾水平滚动偏移，
导致开头的 `0` 被视觉裁掉，截图中看起来像 `).3333333`。几何边界测试只能证明框没有
超出视口，无法发现文本滚动位置错误。

## 实现修改

- 在 `_draw_edit_hop_controls()` 创建新跃迁系数框并设为居中对齐后，显式调用
  `setCursorPosition(0)`；所有因参数提交、主题切换和界面缩放触发的重建都会从完整文本开头显示；
- 不改变用户获得焦点后的输入行为，输入时光标仍由用户操作控制；不改变解析值、参数归一化或
  哈密顿量计算；
- 将最新 180% 深色跃迁编辑截图替换为修复后版本：
  [10-hop-editor-dark-180.png](../assets/screenshots/10-hop-editor-dark-180.png)。

## 验证

- 新增回归测试 `test_rebuilt_fraction_editor_keeps_leading_zero_visible_at_large_scale`：实际
  提交 `1/3`，触发模型重建，再切换深色 180%，检查文本以 `0.` 开头、光标位置为 0、文本宽度
  不超过可用控件宽度；
- 定向测试：`2 passed, 158 deselected in 2.64s`；
- 重新运行 `tools/render_ui_regression.py --hop-editor-demo --ui-scale 1.8`，完整窗口截图为
  `1920×1200`，首字符和输入框边框均可见；
- 合并后全量测试：`312 passed in 116.47s`；全预设编辑器审计 `88/88` 通过；仅用于复核的临时
  截图已清理，正式证据目录保持可控规模。

## 兼容性与风险

- 无破坏性 API 或模型格式变更；
- 仅调整新建编辑器的初始水平滚动位置，避免合法数值的视觉误导；
- 本次变更与已有代理几何同步修复互补：前者保证文本完整，后者保证控件边框完整。
