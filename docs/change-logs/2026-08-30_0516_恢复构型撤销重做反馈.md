# 恢复构型撤销重做反馈

- 时间：2026-08-30 05:16 +08:00
- 范围：`hamivisualizer/view/main_window.py`、`hamivisualizer/tests/test_ui_hardening.py`、`tools/render_ui_regression.py`
- 目标：让“恢复编辑前构型”与 `Ctrl+Z`/重做形成可理解、可恢复的连续操作，并避免历史回放异常后锁死后续历史记录。

## 发现的问题

编辑态的几何恢复本身会创建历史快照，但撤销/重做没有即时反馈；更隐蔽的问题是历史回放通过标志位抑制 `document_committed` 的重复入栈，如果应用快照时抛出异常，标志位可能一直保持为真，之后用户的正常编辑就不会再进入撤销栈。

## 实施内容

1. `MainWindow.undo()` 与 `redo()` 在回放控制器文档时使用 `try/finally`，无论计算或文档校验是否异常，都会清理 `_history_replay`。
2. 撤销/重做成功后通过底部状态栏给出短暂红色高亮反馈，并复用历史快照的语义标签，例如“已撤销：移动或编辑格点”；不新增顶部横幅，不遮挡画布。
3. 新增回归测试，覆盖：
   - 几何恢复会进入历史；
   - 撤销恢复前的移动，重做回到恢复后的几何；
   - 回放结束后再次编辑仍可继续写入历史。
4. 新增 `--restore-history-demo` 离屏验收场景，在隔离工作区内执行“移动 → 恢复 → 撤销”，并在 80%/100%/150%/180% 界面缩放、浅色/深色主题下各保存一张图。

## 兼容性与影响

- 无破坏性接口变更；模型文件格式不变。
- 状态栏反馈只在成功撤销/重做后出现，原有手动计算、编辑恢复和历史标签语义保持不变。
- 若控制器在回放快照时确实抛出异常，异常仍按原路径向上传递，但内部回放标志不再泄漏到后续编辑。
