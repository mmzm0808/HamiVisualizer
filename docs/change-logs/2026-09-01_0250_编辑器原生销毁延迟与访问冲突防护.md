# 编辑器原生销毁延迟与访问冲突防护

- 完成时间：2026-09-01 02:50:16 +08:00（北京时间）
- 影响范围：晶格编辑器中的嵌入式跃迁系数输入框、场景重建、主题切换、编辑态关闭路径
- 变更性质：兼容性/稳定性修复；不改变模型文件格式、哈密顿量计算、跃迁语义或公开交互入口

## 现象与用户影响

Windows 原生窗口在编辑晶格、移动格点或切换视图后，可能弹出 `python.exe - 应用程序错误`，提示某条指令读取了 `0xFFFFFFFFFFFFFFFF`。同一类场景还可能出现旧输入框或旧格点圆在重建后的画面中残留。问题集中出现在晶格画布使用 `QGraphicsProxyWidget` 嵌入真实 `QLineEdit` 的路径，普通矩阵/能带纯图元不经过该销毁链路。

## 根因分析

旧实现会在 `LatticeView.set_data()` 的当前调用栈内完成以下动作：

1. 隐藏并解绑旧 `QLineEdit`；
2. 调用 `deleteLater()`；
3. 清空 `QGraphicsScene`，同步销毁代理图元；
4. 立刻对旧控件调用 `QCoreApplication.sendPostedEvents(..., DeferredDelete)`。

`set_data()` 可能由焦点变更、鼠标释放、主题/缩放回调或绘制相关回调间接触发。此时 Windows Qt 的代理控件和 backing-store 仍可能持有旧原生指针，当前栈内强制处理 `DeferredDelete` 会把控件从“正在处理事件”状态直接推进到析构，形成访问冲突窗口。仅依赖 Python 异常捕获无法覆盖这种原生层崩溃。

## 实施改动

### 1. 两阶段代理回收

- 重建前先禁止旧输入框信号、清除焦点、隐藏控件并隐藏代理，再执行 `proxy.setWidget(None)`；
- 旧控件加入场景自有的 `_retired_editor_widgets` 保活列表，防止无父控件的 Shiboken 包装对象过早回收；
- `QGraphicsScene.clear()` 后不再同步刷新 Qt 删除队列；
- 新增场景自有单次计时器 `_editor_cleanup_timer`，待当前鼠标/焦点/绘制事件完全返回后，仅处理本次重建登记的控件；
- 清理函数对平台关闭过程中已经失效的 Qt 包装器做 `RuntimeError` 兜底，不让失效对象反向拖垮后续重建。

### 2. 保持既有用户体验

- 新场景仍在同一次 `set_data()` 中完成，系数编辑器不会因延迟清理而少显示或跳到随机位置；
- 延迟窗口只存在于一个事件循环回合，旧控件不可见、不可获得焦点、不可拦截鼠标；
- 右侧系数栏、悬停系数提示、吸附网格和矩阵计算路径均未改动；
- 旧格点圆的“单一视觉来源”规则保持不变，编辑手柄仍不会和快照圆重叠。

## 风险与后续

本修复针对已定位的 Qt 代理销毁竞态；由于访问冲突发生在原生层，无法用 Python `try/except` 保证拦截，因此将“禁止当前栈同步析构”作为核心不变量。若用户仍能复现崩溃，下一步应记录具体操作序列、环境版本和是否在关闭窗口时发生，再增加对应的原生最小复现，不应盲目扩大清理范围。
