# 斜元胞跃迁引导线一致性

- 完成时间：2026-08-28 21:38 +08:00
- 状态：完成
- 影响范围：晶格编辑态的跃迁引导线、跃迁系数输入框定位、任意斜元胞向量。

## 发现

编辑器为跃迁系数输入框绘制的引导线，端点计算只加入了 `off_y · a₂` 的竖直分量，漏掉 `off_x · a₁` 的竖直分量。默认蜂窝模型的 `a₁` 恰好水平，因此常规截图看不出；当用户编辑元胞方向使 `a₁_y ≠ 0` 时，输入框和引导线会偏离真实跃迁端点，出现“线和框对不上”的问题。

## 修复

- 引导线端点现在严格按 `r_to = r_from + off_x·a₁ + off_y·a₂` 计算，与 Hamiltonian 使用同一套位移语义；
- 保留固定像素输入框的完整边框、碰撞避让和视口安全边界逻辑，修复只影响遗漏的几何分量，不改变跃迁矩阵数值；
- 离屏回归工具增加一次性 `--oblique-a1-demo`，在项目截图目录内生成斜元胞实景，验证框、线和元胞轮廓同步倾斜。

## 验证

- 斜 `a₁` 端点单元测试与输入框边界测试：`2 passed`。
- 完整晶格界面回归：`68 passed in 17.99s`。
- 默认预设/物理模型回归此前 `21 passed`，本修复未改变计算层；编译检查与差异检查通过。
- 实景截图：[蜂窝斜元胞 + 跃迁输入框 · 深色 150%](../../.codex-artifacts/screenshots/oblique-editor-audit-20260828/honeycomb-oblique-a1-row1-dark-150.png)。截图中 `a₁=(1.73205081, 0.45000000)`，输入框引导线与斜元胞端点一致，边框完整可见。

## 兼容性

- 不改变模型文件格式、默认晶格坐标、周期边界或哈密顿量计算。
- 任意第三方模型只要提供合法元胞向量，编辑器都会使用完整二维位移；水平元胞的视觉结果保持不变。
