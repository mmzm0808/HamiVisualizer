# 画布跃迁系数分数输入

- 时间：2026-08-29 12:17（+08:00）
- 范围：`hamivisualizer/view/lattice_view.py`、`hamivisualizer/tests/test_ui_hardening.py`。
- 目标：让画布上点击跃迁线后出现的系数输入框，与左侧参数面板保持一致，支持用户直接填写 `1/3`、`3/10` 等比例值；同时确保提交后的显示稳定、错误输入不会触发重建。

## 问题与影响

画布编辑器原来安装了 `QDoubleValidator`，只接受十进制数字。左侧参数表已经支持安全的分数输入，因此同一模型在两个入口的输入能力不一致：用户可以在参数表输入 `1/3`，但点击具体跃迁线后输入同样内容会被编辑器拒绝或留下不明确的状态。对蜂窝模型设置胞内/胞间比例时，这会增加不必要的换算步骤。

## 实施修改

1. 在晶格视图新增 `_parse_positive_strength()`：
   - 先解析普通有限正数；
   - 普通转换失败后仅交给 `fractions.Fraction` 解析分数；
   - 拒绝空值、零、负数、NaN/Inf、除零和任意其他表达式，不引入代码执行入口。
2. 移除画布输入框的十进制专用验证器，改为提交时验证。这样用户可以自然地分两步输入斜杠，不会被即时验证器打断。
3. 输入框增加 `例如 1/3` 占位提示和完整 tooltip；成功提交后将显示规范化的小数（物理信号仍传递完整浮点值），保持后续编辑和截图一致。
4. 原有系数归一化逻辑保持不变：控制面板收到绝对强度后，会在同名跃迁组内计算最简整数比并更新参数基准。例如依次设置 1.2 与 0.3，最终仍得到 `4*t`、`t` 且 `t=0.3`。

## 验证

- 新增分数输入单元测试：`1/3`、带空格的 `3 / 10`、普通小数均通过；`1/0` 与 `-1/3` 均被拒绝。
- UI 专项：`111 passed, 1 warning in 57.84s`；警告仍是既有 Windows 中文路径 `.pytest_cache` 权限提示。
- 编译：`python -m compileall -q hamivisualizer` 通过。
- 全量回归：`237 passed, 1 warning in 149.53s`；新增分数输入后没有回归，唯一警告仍是既有 Windows 中文路径 `.pytest_cache` 权限提示。
- 已生成画布编辑器多缩放截图（80%、100%、150%、180%，浅色/深色各一张），确认输入框完整边框、底边、占位区域和邻近格点在不同界面缩放下均可见：[系数编辑器多缩放审计组](../../.codex-artifacts/screenshots/coefficient-editor-audit-20260829/)。
- 另在真实编辑态输入 `1/3` 后抓取了现场画面，字段显示完整的分数文本且焦点边框未裁切：[实际输入 1/3 的编辑态截图](../../.codex-artifacts/screenshots/coefficient-editor-audit-20260829/kagome-coeff-fraction-dark-100.png)。

## 兼容性与风险

- 没有改变模型 JSON、`HoppingTerm` 或对外信号签名；只是扩展画布字段的输入语法。
- 画布字段仍只接受正的“绝对跃迁强度”，负号/相位继续由幅度、相位和符号列表达，避免把相对比例与 Hermitian 相位混淆。
- 全量测试若只出现已知 `.pytest_cache` 权限警告，不视为功能回归；任何新增失败都需在持续简报中单独记录。
