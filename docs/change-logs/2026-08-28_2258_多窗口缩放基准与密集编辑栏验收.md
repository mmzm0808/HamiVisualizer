# 多窗口缩放基准与密集编辑栏验收

- 时间：2026-08-28 22:58 +08:00
- 范围：多模型窗口连续切换后的 UI 缩放、180% 密集编辑状态、控制栏可达性

## 问题与根因

连续打开多个模型标签/窗口后，应用字体是进程级状态。旧逻辑在新建 `MainWindow` 时直接读取当时的 `QApplication.font()` 作为“基准”，再乘以目标缩放比例。这样会把前一个窗口已经放大的字体再次放大，最终导致控制栏 sizeHint 超出滚动视口，用户看到不必要的横向滚动或控件漂移。

## 修改

- 为 `QApplication` 保存一次 canonical UI 字体基准；每个窗口都从该基准计算 80%–180% 比例，连续创建窗口不会累积缩放；
- 控制栏面板采用水平忽略 sizeHint 的伸缩策略，并关闭控制栏自身横向滚动条；面板内容优先在可用宽度内重排，垂直方向仍可滚动；
- 不改变表格的精确检查能力：跃迁表在高级列较多时仍可使用表格内部的横向滚动查看完整字段，侧栏本身不再被表格撑宽；
- 新增回归测试覆盖 1440×920、180% UI、格点组/跃迁组同时展开、`dx/dy/相位模式/符号` 高级列展开，以及元胞矢量与底部计算按钮的水平可达性。

## 实景验收

- 蜂窝模型在 180% 深色编辑态下，控制栏右侧只出现垂直滚动条；元胞矢量输入框、应用按钮和立即计算按钮都在侧栏水平可视范围内；
- 矩阵与晶格视图仍保持可见，晶格元胞轮廓、节点和跃迁线没有因控件缩放发生额外裁切；
- 截图证据：[蜂窝密集编辑栏 · 180%](../../.codex-artifacts/screenshots/dense-edit-180-audit-20260828/honeycomb-dense-edit-180.png)。
