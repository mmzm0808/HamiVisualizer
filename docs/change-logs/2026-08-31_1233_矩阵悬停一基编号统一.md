## 一、问题定位

矩阵四边标尺、单击选中详情、状态栏和复制文本已经统一使用从 1 开始的数学坐标，但两条悬停路径仍直接插入 Python/NumPy 的零基循环下标：

1. 底层单元格矩形的 tooltip 显示 `H[0,0]`；
2. 缩放后创建的 `MathTextItem` tooltip 也显示 `H[0,0]`。

这不会导致数值计算错误，但会让用户在“标尺为 1:1、悬停却为 0:0”的同一个界面中得到矛盾结果，属于真实的交互一致性缺陷。

## 二、修改内容

1. 保留 `item.setData(0, (i, j))` 中的零基坐标，确保点击、数组访问和既有接口不变。
2. 底层单元格矩形 tooltip 改为 `H[i + 1,j + 1]`。
3. 放大后懒创建的数学文字 tooltip 同步改为 `H[i + 1,j + 1]`，避免“未显示文字时正确、显示文字后又变回零基”。
4. 新增回归测试，同时遍历图形矩形和数学文字项，确认 `H[1,1]`、`H[2,2]` 存在且不得出现行或列 0。
