# 进程退出与预览线程收口

- **记录时间**：2026-09-01 03:59:53 +08:00（Asia/Shanghai）
- **范围**：主程序退出、分屏比较预览、后台能带/波函数计算、Qt/NumPy 原生资源释放
- **性质**：Windows 稳定性加固；不改变模型格式、矩阵数值、能带或波函数物理语义

## 问题

用户提供的 Windows 错误窗口属于原生层访问冲突（`python.exe` 访问了无效地址）。前一轮已
处理可见主窗口的控制器和编辑器，但继续检查后发现还有两条退出路径可能绕过这层保护：

1. 分屏比较为未打开的大模型创建隐藏 `MainWindow`，其 `ViewController` 也可能因大矩阵启动
   后台谱计算；预览完成后若直接 `deleteLater()`，控制器的 Qt 对象树可能先于 NumPy/LAPACK
   返回而被销毁；
2. 主窗口关闭后 `app.exec()` 返回时，若 QRunnable 仍在全局线程池中运行，Python 解释器可能
   开始卸载 Qt/NumPy 原生库，造成退出阶段的悬空访问。

## 实施

- 隐藏预览的 `apply_document()` 现在放在 `try/finally` 中；无论构建成功或异常，都会先调用
  与主窗口相同的幂等 `controller.shutdown()`，再安排预览窗口销毁；后台 worker 会进入既有
  的安全隔离区，不会把回调发送到已失效的预览控件；
- 隔离区释放回调使用 `Qt.DirectConnection`。它只修改进程内的 worker 集合，不需要 GUI 事件
  队列，因此即使事件循环已经退出、隐藏预览没有下一帧事件，worker 完成后也会立刻释放最后
  的强引用；
- 主入口连接 `QApplication.aboutToQuit` 作为最后一道关闭保险，并在 `app.exec()` 返回的
  `finally` 中再次调用幂等收口，然后等待全局线程池清空。不可安全强制中断的 LAPACK 运算
  仍然自然完成，但解释器不会在工作线程结束前卸载原生库；
- 新增大模型分屏预览回归，覆盖 `9×9` OBC（触发异步谱路径）、预览销毁、线程池等待和隔离
  区归零；不增加新的用户操作或破坏性接口。
